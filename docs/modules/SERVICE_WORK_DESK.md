# Connected service desk — 7 October 2026

Source: [123-section implementation specification](../plans/CUSTOMER_SERVICE_TICKETS_QUERIES_SPEC.md). This replaces the old Tickets placeholder description and extends the preserved Customer Service foundation. Historical 241-section requirements and deployment evidence remain in their original files.

## Record ownership

Customer cases (`ServiceCase`, new `CS` references) belong to Customer Service and the canonical Party. Internal tickets and cross-team queries share `ServiceWorkItem` with distinct TICKET / QUERY kinds and `TKT` / `QRY` references. A query requires an accessible originating case or work item. Historical `CASE` cases and departmental `ServiceTicket` records remain intact; they continue to block resolution while unfinished. Team work never changes the case owner or resolves its parent automatically.

Core owns reusable work access, clocks, numbering, history, evidence, approval connections and request contracts in `src/core/service-work/`. Modules expose typed credit, operation, survey and Sales projection providers through the registry. Core imports no module implementation. Canonical Sales, Finance, Logistics, Quality, Inventory and CSAT records remain authoritative.

## Delivered behavior

- Case purchase picker loads scoped customers, contacts, recent orders, PO/product search, selected order lines and related deliveries. Product must match the order line; affected whole quantity is validated against live order and selected delivery. Manual product complaints retain an explicit unverified purchase flag. Purchase links are stored for source feedback and manager sign-off.
- Focused case tabs: Summary, Timeline, Investigation, Linked work, Remedies & Finance, Satisfaction. Timeline filters distinguish communication, notes, investigation and system history. Phone interactions are manual records. The future telephony contract installs no provider.
- Shared queues support restricted membership, optimistic configuration editing, SLA calendars, case routing criteria, configurable case types/categories and a service catalogue with saved custom form definitions. Ticket impact and urgency remain distinct; an override requires a reason. Queue membership governs assignment and private notes. A manager never bypasses restricted membership.
- Business-hours response/resolution targets use a timezone, weekdays, holidays and saved policy snapshot. Resolution pause/resume extends the deadline by actual working minutes. Late completion remains breached. Attention surfaces show overdue work; response and resolution outcomes are separate from elapsed-time report averages.
- Tickets support incident/request/task/problem/change/access types; contextual investigation, root cause, workaround, risk, implementation, rollback, test and schedule fields; assignment, requester-visible replies, receiving-team internal notes, following, child work and independent Core approvals. Required evidence and approval block resolution. Child work blocks parent completion. Reopen/merge preserve original history.
- Query creation from a case or ticket retains its origin and minimal purchase identifiers, affected quantity and lot code. Answered work prompts Customer Service to update the customer. The parent receives a safe linked-work event; confidential response text is read only from permitted query detail. Customers never become internal ticket requesters merely because a case is linked.
- PDF/PNG/JPEG evidence up to 8 MB is stored only in configured private server storage. Downloads re-check tenant and parent permissions. No desktop evidence directory, browser business cache or local database is created.
- Case emails use existing company/personal mail infrastructure. Existing IMAP sync appends known-contact replies only to matched outbound threads, with unique ingestion source keys. Arbitrary inbound email-to-ticket intake is not implemented.
- Credit requests create CR references and canonical DRAFT AR credits using the affected invoice line, proportional source tax and net quantity/value. Source tenant/customer/product/order line and pending/previous credits are validated. Request replay cannot reuse a key with different source/value. A request never posts or changes balances. Finance has a Credits & adjustments review list; independent approval and separate manual posting remain mandatory. Paid-invoice refunds require Finance review and are not represented as unpaid credits.
- Returns create canonical RMA requests against delivered quantities; replacements create Sales drafts preserving source price and tax classification; Quality creates NCRs. No remedy request mutates stock. Return receipt was hardened: authorised quantity cap, exact replay checks, quarantine stock and receipt updates in one serializable transaction. Inventory owns subsequent disposition.
- Recovery benefits support capped percentage or fixed discount, expiry, minimum order, currency and usage limit. Independent approval precedes Sales visibility. Sales explicitly applies the benefit to an eligible draft order with canonical tax recalculation, redemption history and concurrency protection. Company price lists remain unchanged.
- Resolution queues an existing active Support/Customer Service CSAT survey after 30 minutes, with known contact, suppression, seven-day cooldown and unique source key. Scores and comments each have one atomic submission; managers may exclude invalid responses with an audit reason while retaining originals. Low scores append recovery-needed evidence to the case. No external SMTP/IMAP delivery is claimed without configured mail and verification.
- Reports show observed response/resolution averages with sample sizes, team workload, categories, root causes, reopens and completed target outcomes. Posted credit gross and redeemed discount net costs are reported separately by currency. Missing freight, replacement, labour and goodwill costs are never estimated.

## Security and data

Tenant and enabled/entitled-app scopes apply server-side. Restricted case permission remains additional; restricted queues add membership/owner protection. Requesters cannot read receiving-team private notes. Mutation permissions, independent approvals, optimistic versions and serializable dependency/financial operations remain authoritative. Audit and durable events contain IDs rather than unrestricted complaint content. Server-only evidence files have opaque keys and private permissions.

Migration `20261007190000_service_work_desk` adds service work/history/files/recovery/redemptions/knowledge, context/clock/merge fields, unique source keys and CSAT integrity fields. It preserves all existing rows and backfills only historical comment submission timestamps. No table or column is removed.
